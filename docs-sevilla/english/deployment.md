# PIA-LARA Production Deployment

The deployment of the PIA-LARA application is managed using Docker containers, orchestrated through Docker Compose. This allows for a predictable and replicable execution environment, ideal for deployment on instances like AWS EC2. The architecture consists of three main services: the database (MongoDB), the web application (Flask served with Gunicorn), and a reverse proxy (Nginx) that also handles secure traffic (HTTPS).

Below is a detailed explanation of how the different architecture components interact and the configuration of each key element of the deployment.

## Deployment Architecture

The architecture is based on a multi-container environment that isolates each component:

1.  **Reverse Proxy (Nginx)**: Acts as the single public entry point, receiving HTTP/HTTPS requests, securely redirecting traffic to the application container, and handling SSL termination with certificates.
2.  **Web Application (Pialara)**: Runs the Flask code through Gunicorn, a production WSGI server, to handle multiple concurrent requests. This container uses configuration injected via environment variables and `.ini` files to maintain compatibility with the current structure.
3.  **Database (MongoDB)**: Dedicated container that stores all user, audio, and model information, with persistent storage in a local volume.

### Dockerfile (Web Image Build)

The `Dockerfile` defines the instructions to build the web application image:

-   **Base Image**: Uses `python:3.9-slim-buster`, a reduced version of Debian with Python 3.9 pre-installed, minimizing the final image size.
-   **Environment Variables**: Sets `PYTHONDONTWRITEBYTECODE=1` and `PYTHONUNBUFFERED=1` to avoid unnecessary `.pyc` compiled files and ensure application logs are emitted immediately (unbuffered) to the standard Docker output.
-   **Working Directory (`/app`)**: Defines where the following commands will be executed and where the code will reside.
-   **Dependencies**: Copies `requirements.txt` and installs necessary packages (along with Gunicorn) using `pip install --no-cache-dir` to not keep the cache and save space.
-   **Audio Directory**: Explicitly creates the local directory at `/app/pialara/static/audios` to avoid possible mounting or writing errors when persisting files generated by the application.
-   **Exposure and Execution**: Exposes port `8000` (Gunicorn listening port within the private container network) and specifies the application execution with `gunicorn --workers=4 --bind=0.0.0.0:8000 pialara:create_app()` as the default command, using 4 workers to handle concurrency.

### `docker-compose.yml` File (Service Orchestration)

The `docker-compose.yml` declares how services are grouped and communicate with each other on the same private network (`pialara_net`):

-   **`db` Service**:
    -   Uses the official `mongo:6.0` image.
    -   Configures a volume named `mongo-data` pointing to `/data/db` inside the container to ensure data persists across crashes or restarts.
-   **`web` Service**:
    -   Built from the `Dockerfile` located in the current directory.
    -   Defines a direct dependency on `db` (`depends_on: db`) to start after the database.
    -   Uses volumes to inject configurations: injects `produccion.ini` into `/app/.ini`, preserving the use of `.ini` files for configuration, as required by the current design.
    -   Maps the `./audios_local` directory to the internal path `/app/pialara/static/audios` of the container. This is essential so all saved audios are not deleted if the container stops.
-   **`cert-generator` Service**:
    -   Is an ephemeral service (runs, does its job, and finishes). Checks if an SSL certificate already exists in the `certs` volume. If it doesn't exist, it generates a self-signed one using `openssl`. This way, the proxy server will always have a certificate without requiring manual intervention during startup.
-   **`proxy` Service (Nginx)**:
    -   Will expose and publish ports `80` (HTTP) and `443` (HTTPS) on the host machine (AWS).
    -   Maps the custom `nginx.conf` configuration as read-only, and injects the `certs` volume generated by the `cert-generator`.
    -   Its execution requires that the `web` service has started and the `cert-generator` has successfully finished.

### `nginx.conf` File (Network and Security Configuration)

This file structures the behavior of Nginx, which operates as the front end:

-   **HTTP to HTTPS Redirection**: The first `server` block listens on port `80` and forces all clients by redirecting traffic with a `301` to the same URI but via HTTPS.
-   **SSL Termination**: The second block listens on port `443 ssl` and specifies the paths where Nginx finds the certificates (`/certs/server.crt` and `/certs/server.key`). It also secures the server by limiting allowed secure protocols to `TLSv1.2` and `TLSv1.3`.
-   **Proxy to Web**: Inside the `location /` directive, all validated requests are forwarded to the internal web container via `proxy_pass http://web:8000`. Additionally, Nginx injects headers such as `Host`, `X-Real-IP`, `X-Forwarded-For`, and `X-Forwarded-Proto`, which inform the Flask web application (via Gunicorn) of the original client's identity and that the request came from a secure connection, preventing flaws in redirection and security schemes specific to Flask.

## Steps for AWS EC2 Instance Deployment

To deploy the PIA-LARA application on an Amazon EC2 instance, these structured steps must be followed:

1.  **EC2 Instance Creation**: 
    - Launch an instance from the AWS dashboard (Ubuntu Server 22.04 LTS or later is recommended).
    - Configure the associated **Security Group** to allow inbound traffic on ports **80** (HTTP), **443** (HTTPS), and **22** (SSH).

2.  **Server Connection**: 
    - Connect to your instance via SSH using the downloaded key (`.pem`):
      ```bash
      ssh -i "your_key.pem" ubuntu@<EC2_PUBLIC_IP>
      ```

3.  **Dependencies Installation**:
    - Update repositories and install Docker and the Docker Compose plugin:
      ```bash
      sudo apt-get update
      sudo apt-get install -y docker.io docker-compose-v2 git
      ```
    - (Optional) Add your user to the docker group to run without `sudo`:
      ```bash
      sudo usermod -aG docker ubuntu
      ```

4.  **Project Download**:
    - Clone the PIA-LARA project repository or upload the deployment files via SFTP/SCP.
      ```bash
      git clone <REPOSITORY_URL> pialara
      cd pialara/pia-lara
      ```

5.  **Production Variables Configuration**:
    - Create the production `.ini` file from the template:
      ```bash
      cp produccion.ini.template produccion.ini
      ```
    - Modify `produccion.ini` with the credentials corresponding to your production environment. This configuration will be automatically mapped to the `web` container.

6.  **Deployment with Docker Compose**:
    - Once in the directory containing the `docker-compose.yml`, build the images and start the services in the background (`-d`):
      ```bash
      sudo docker compose up -d --build
      ```

7.  **Verification**:
    - Access your AWS instance's public IP from a browser (e.g., `https://<EC2_PUBLIC_IP>`). 
    - The `cert-generator` container will have created the SSL certificate automatically, Nginx will redirect HTTP traffic to HTTPS, and the Flask application will be running, ready to use, backed by MongoDB.
